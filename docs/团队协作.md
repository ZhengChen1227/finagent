# 团队协作与分发包使用说明

本文面向**队友**：如何在三分钟内把项目跑起来，以及如何在多台机器上保持同一套结果。

---

## 一、最快路径：克隆仓库

```bash
git clone https://github.com/ZhengChen1227/finagent.git finagent
cd finagent

# 建虚拟环境（Python 3.12）
python -m venv .venv
.venv\Scripts\activate          # Windows PowerShell
# source .venv/bin/activate      # macOS / Linux

pip install -r requirements.txt
python tests/check_env.py        # 核对依赖版本
```

然后双击 `启动FinAgent应用.bat`，浏览器会自动打开界面。

---

## 二、配置 DeepSeek 密钥（两种方式，任选其一）

### 方式 A：在界面里填（推荐，队友无需碰命令行）

1. 打开应用，切到左侧 **环境与口径** 页
2. 在 **推理引擎配置** 里填入：

   | 字段 | 值 |
   |---|---|
   | 接口地址 | `https://api.deepseek.com/v1` |
   | 模型名称 | `deepseek-chat` |
   | API Key | 你自己的 `sk-...` |

3. 点 **保存配置**

密钥会写入本机的 `config.local.yaml`。该文件已列入 `.gitignore`，
**不会**进入版本库，也**不会**出现在打包分发的压缩包里。
界面回显时密钥一律打码，只保留首尾各 3 位。

### 方式 B：设环境变量（适合临时切换或 CI）

```powershell
$env:FINAGENT_API_KEY = "sk-xxxx"
$env:FINAGENT_BASE_URL = "https://api.deepseek.com/v1"
$env:FINAGENT_MODEL = "deepseek-chat"
```

配置优先级：内置默认值 < `config.yaml` < `config.local.yaml` < 环境变量。

**没有密钥也能跑。** 未配置时系统自动降级为确定性离线归因，
规则引擎、指标计算、勾稽校验、报告生成的能力与结果完全一致，
只有"归因推理"这一段由大模型换成离线模板，报告里会注明推理模式。

## 三、构建封闭数据环境

竞赛要求作品在**封闭或半封闭数据环境**中运行。这一步把公告原文抓到本地：

```bash
python run.py fetch                  # 抓取配置内公司的公告原文
python run.py fetch --code 002714    # 只抓某一家（支持简称与代码）
python run.py index                  # 抽取 PDF 文本并建立全文索引
```

完成后，检索与引用全部基于本机文件，运行期不再访问外网。

`data/corpus/` 约 74MB，默认**不入库**。三种分发方式：

| 方式 | 做法 | 适用 |
|---|---|---|
| 各人自行抓取 | 队友跑一次 `run.py fetch` | 网络通畅，最干净 |
| 网盘分发 | 把 `data/corpus/` 压缩后单独发给队友 | 队友网络受限 |
| 直接入库 | 把 `.gitignore` 里 `data/corpus/` 一行注释掉再提交 | 希望克隆即得，仓库会变大 |

## 四、日常分工建议

| 角色 | 主要工作面 |
|---|---|
| 取数与口径 | `finagent/datasource/`、`config.yaml` |
| 指标与校验 | `finagent/metrics/`、`finagent/validate/` |
| 智能体与报告 | `finagent/agent/`、`finagent/report/`、`finagent/skills/` |
| 界面与演示 | `app/`、`docs/`、演示脚本与视频 |

无论分工如何，提交前都要跑一遍：

```bash
python tests/run_all.py
```

刚克隆下来时，`应用界面与接口` 这一套会显示 **4 项跳过**，这是正常的：
公告原文与全文索引体积大、不入版本库，所以「语料已落盘」「索引已建立」
「公告原文清单」「轨迹可枚举」这四项在构建数据环境之前无从断言。
跳过时会打印需要执行的命令。跑完上面第三节的 `fetch` + `index`，再跑一次即为全绿。

**判读原则**：跳过说明"前置条件还没做"，失败才说明"功能坏了"。
如果看到失败，先看它输出的是哪一种。

## 五、常见问题

**Q：界面显示"密钥未配置"，但我明明填了？**
检查是否点过 **保存配置**。读写的是项目根目录的 `config.local.yaml`，
确认该文件存在且 `api_key` 字段非空。

**Q：某家公司分析时被 `[跳过]`？**
说明三张报表都没取到数据。请看 `output/traces/` 里对应的记录，
区分是"确实没有披露"还是"网络请求失败"——两者在系统里是不同状态。

**Q：报告里的结论能追到出处吗？**
能。每个数值带证据 ID，可回溯到数据源字段与计算公式；
引用公告原文的结论标注公告名称与页码，可用 `read_page` 逐字核对。
若本地尚未抓取该公司的公告原文，报告头部会明确写出"证据强度提示"。

**Q：两人跑同一家公司结果会不一样吗？**
不会。取数与语料都有本地缓存，指标计算完全确定。
唯一可能不同的是"归因推论"——它依赖大模型，因此报告中与事实分区呈现。
