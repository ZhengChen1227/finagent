# FinAgent 使用指南

> 面向使用者（队友、演示观众、评审）。目标：从零到跑出第一份报告，全程不超过 10 分钟。
> 开发规范与禁止事项见 `AGENTS.md`，复现材料清单见 `docs/复现清单.md`。

---

## 一、开始之前

### 你需要准备什么

| 项目 | 要求 | 备注 |
|---|---|---|
| 操作系统 | Windows 10 / 11 | 启动脚本是 `.bat`；其它系统可手动跑 `python app/server.py` |
| Python | 3.10 或更高 | 安装时**务必勾选 `Add python.exe to PATH`** |
| DeepSeek API Key | 一个，形如 `sk-...` | 到 platform.deepseek.com 申请，费用自付；系统不做任何替代方案 |
| 财报 PDF | 至少一份定期报告 | 年报 / 半年报 / 一季报 / 三季报的**完整版** |
| 浏览器 | Edge 或 Chrome | 导出 PDF 时用它们的打印引擎 |

### 什么时候需要联网

- 装依赖（一次）→ PyPI 或镜像站
- 跑分析（每次）→ `api.deepseek.com`，这是**唯一**的对外请求

除此之外，包括读财报、算指标、做校验、出报告，全部在本机完成。

---

## 二、安装（只做一次）

1. 把仓库下载或克隆到本地任意目录（路径里**建议不要有空格**，例如 `D:\FinAgent`）；
2. **双击 `一键安装依赖.bat`**；
3. 等待脚本依次完成：检查 Python 版本 → 创建 `.venv` → 安装依赖 → 环境自检；
4. 看到下面这行就是成功了：

```
============================================================
  安装完成。以后双击「启动FinAgent应用.bat」即可使用。
============================================================
```

**装不上怎么办**

- 提示找不到 python → 装 Python 时没勾 PATH，重装并勾上；
- pip 安装超时 → 脚本会自动换官方源重试；仍失败则换镜像，例如
  `.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple`；
- 其它报错 → 把完整输出发给队友，不要自己猜。

---

## 三、启动

**双击 `启动FinAgent应用.bat`**，然后：

- 会自动设置 UTF-8 环境、找到 `.venv`、启动服务；
- 浏览器自动打开 `http://127.0.0.1:8765`；
- **那个黑色命令行窗口就是服务本体，关掉它服务就停了。**

服务只监听本机回环地址 `127.0.0.1`。这意味着：

- 别人访问不到你的机器，你的财报不会外泄；
- 反过来，**你不需要和队友在同一个网络下**——每人各自跑自己的一份代码，
  各自的 Key、各自的财报、各自的产物，互不依赖，也不需要任何人保持开机。

---

## 四、填一次 API Key

1. 点界面右上角的「**填写 API Key**」（未配置时会显示「未配置密钥」）；
2. 粘贴你的 DeepSeek API Key；
3. 选模型：

| 模型 | 特点 | 建议 |
|---|---|---|
| `deepseek-chat` | 快、便宜 | **默认选它** |
| `deepseek-reasoner` | 推理更深，更慢更贵 | 想让归因推理更细时用 |

4. 点「**测试连接**」——会真的发一次请求验证 Key 是否可用；
5. 点「**保存**」。

保存后 Key 落在项目根目录的 `config.local.yaml`，**该文件已在 `.gitignore` 中，永远不会被提交**。
界面上的「记住本次填写」只是把内容暂存在你自己浏览器的本地存储里，方便下次自动填上；
换电脑必须重新填写。

> 接口地址固定为 `https://api.deepseek.com/v1`，界面不提供修改入口。
> 允许改地址等于允许把财报正文发到任意服务器，这条线不放开。

## 五、上传财报

把 PDF **拖进上传区**，或者点「选择文件」挑。可以一次多份。

上传完成后，每份文件会显示系统从 PDF 正文里解析出的：

- **主体**（公司全称 / 简称 / 股票代码）
- **报告期**（例如 2026-06-30）
- **报告类型**（年报 / 半年报 / 一季报 / 三季报）
- **抽到多少科目、校验通过多少项、有没有可疑项**

### 关于文件本身

- **必须是完整版定期报告。** 摘要版、摘编版、公告正文里只有几张表的"简版"，
  通常没有封面页和完整的「主要会计数据」章节，主体和报告期可能识别不出来，会被标红。
- **扫描件不行。** 图像型 PDF 没有文本层，系统会直接拒绝并提示，不会给出瞎猜的数字。
- **主体识别失败时**，界面会标红要求你确认。此时**不要**指望系统猜——换个完整版本的文件。
- 文件名建议保留原始公告名（如 `2026-08-21_牧原股份_2026年半年度报告.PDF`），
  识别失败时它是兜底线索。

### 一次传多份会怎样

系统按「同一主体 + 可比口径」自动归组配对：

- 同一家的半年报和它的上年同期年报 → 可以算同比；
- 同一家的年报（自带分季度主要财务指标）→ 可以还原单季、算环比；
- 不同主体一起上传 → 各自出一份报告，**外加一份跨主体对照分析**。

**只传一份半年报或季报时，环比是算不出来的**（年内缺上一期累计数）。
报告会如实写"不可计算"，不会编一个数字给你。

## 六、跑分析

1. （选填）在「**定向追问**」里写下你特别关心的问题，例如：
   - `为什么净利润下降幅度远大于收入下降幅度？`
   - `利润和经营现金流为什么背离？`
   - `政府补助等非经常性损益对利润的影响有多大？`
2. 点「**开始分析**」；
3. 运行中界面会实时显示进度；不想等可以点「**停止本次运行**」。

**没填 Key 会被直接拦住**，弹出密钥窗。这是设计如此：宁可当场告诉你缺什么，
也不要让你等半分钟拿到一份"降级版"结论。

分析耗时取决于材料数量和模型：单主体一批材料通常在 1～3 分钟量级。

## 七、看结果

### 分析报告

渲染后的 Markdown 报告。右上角「**下载 PDF**」导出正式版式
（走本机 Edge / Chrome 的打印引擎，不需要额外装东西）。

同时可以去 `output/reports/` 取原始 `.md` 与结构化 `.json`，
去 `output/tables/` 拿指标宽表 `.csv`。

### 指标宽表

一行一个指标，包含：指标名、各报告期数值、同比、环比、口径说明、证据页码。
这是"结构化数据"形态的成果，可以直接丢进 Excel 复算。

### 执行轨迹

系统把每一步都记下来了：读了哪个文件、调了哪个工具、传了什么参数、
算了什么公式、得到什么结果、证据出自哪一页。轨迹是可以逐条重放的，
**任何一个数字都能沿轨迹回溯到财报的具体页码**。

### 运行日志

收在独立的日志抽屉里，不干扰主界面。排查问题时看它。

### 环境与口径

本次运行用的模型、指标定义、阈值来源、复现信息。评审关心"你凭什么这么算"，在这里回答。

## 八、结果怎么读（重要）

报告里的结论分三类，**不要混着看**：

| 类别 | 含义 | 举例 |
|---|---|---|
| **异常信号** | 数据自相矛盾或有明显背离，需要解释 | 净利润为正而经营现金流长期为负 |
| **结构性特征** | 是这家公司商业模式的一部分，不一定是问题 | 重资产行业折旧占比高 |
| **口径提示** | 会计政策 / 口径变化导致的不可比 | 本期发生同一控制下企业合并，上年数已追溯调整 |

还有两类标记必须认得：

- **「需人工复核」** —— 这个科目**没通过交叉校验闸门**。可能是抽取错了行，
  也可能是报告本身的勾稽关系特殊。**引用这类数字前必须人工核对原页码。**
  这不是 bug，是系统在保护你。
- **「不可计算」** —— 材料不足，例如只传了一份半年报却要看环比。
  系统拒绝给数字，而不是给一个看起来合理的假数字。

另外，**事实、推论、观点是分开的**：

- 事实 = 财报里写着的，带页码；
- 推论 = 模型的归因推理，带置信度与验证路径；
- 观点 = 需要人判断的，报告会明说这是判断。

## 九、命令行用法（评审复现推荐）

图形界面方便演示，命令行方便复现：

```bash
python run.py analyze --pdf 财报1.pdf 财报2.pdf     # 分析指定 PDF
python run.py analyze --pdf-dir data/corpus/002714  # 分析目录内全部 PDF
python run.py index --force                          # 为本次上传材料重建全文索引
python run.py mcp                                    # 以 MCP 协议暴露工具集
```

常用参数：

| 参数 | 作用 |
|---|---|
| `--run <上传批次号>` | 复用某次上传目录（含已解析结果），不重新抽取 |
| `--question "..."` | 带上定向追问 |
| `--quiet` | 不打印工具调用过程 |
| `--since-year 2025` | 只保留该年份及之后的规则结论，默认聚焦最近两年 |

`python run.py analyze --help` 可以看全部参数。

## 十、常见问题

| 现象 | 处理 |
|---|---|
| 双击 bat 窗口一闪就没 | 在命令行里手动跑一次看报错；多数是 Python 没装或没加进 PATH |
| 浏览器没自动打开 | 手动访问 `http://127.0.0.1:8765` |
| 提示端口被占用 | 确认没有另一个 FinAgent 窗口还开着；或换端口：`.venv\Scripts\python.exe app\server.py --port 8801` |
| 「测试连接」失败 | Key 无效 / 额度不足 / 网络不通，逐项排查 |
| 上传后主体识别为空 | 换成完整版报告；扫描件无解，需要先做 OCR |
| 报告里全是「需人工复核」 | 说明这份 PDF 的表格结构很特殊。打开轨迹页看是哪一步校验没过，把 PDF 页码反馈给开发 |
| 下载 PDF 没反应 | 本机需要 Edge 或 Chrome；实在没有就用浏览器打印 |
| 想重新开始 | 点「清空本批」清掉本次上传；`output/` 里的历史产物可手动删除 |

## 十一、已知限制

- 银行 / 保险 / 证券的报表格式与工商业差异很大，目前靠同义词与规则兜底，
  **未经真实样本验证**；
- 只上传单份半年报 / 季报时环比不可计算（会如实标注）；
- 万元 / 千元单位的报表已做换算逻辑与合成测试，但没有真实样本验证；
- 少数冷门科目（生物资产折旧、递延收益摊销等）暂无同义词映射，遇到会留空并标注；
- 财报 PDF 的来源、版本与完整性由使用者负责——系统只保证"抽出来的数字自洽"。

## 十二、术语表

| 术语 | 含义 |
|---|---|
| **同比** | 与上年同期相比（本期累计 vs 上年同期累计） |
| **环比** | 与上一期相比。本项目按**单季度**口径还原后比较 |
| **单季还原** | 用本期累计数减去上一期累计数，得到本季度单季数 |
| **扣非归母净利润** | 归属于母公司股东的净利润，扣除**非经常性损益**后的金额 |
| **非经常性损益** | 与公司正常经营业务无直接关系、或虽相关但影响报表使用者判断的损益，如政府补助、资产处置损益 |
| **追溯调整** | 因会计政策变更或同一控制下企业合并，对上年比较数重新表述 |
| **利润与现金流背离** | 账面利润与经营活动现金流方向或量级明显不一致 |
| **canonical 契约** | 抽取层对下游承诺的统一字段名，保证换数据源时下游不用改 |
| **交叉校验闸门** | 抽完数字后的自检：同比对得上吗？资产 = 负债 + 权益吗？对不上就降级 |
