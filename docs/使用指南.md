# FinAgent 使用指南

面向使用者与评审的操作手册。读完这一份，你应该能独立完成从环境搭建到产出报告的
全部流程，并能判断结果是否可信。

---

## 一、一分钟了解

FinAgent 是一个上市公司财务报告分析智能体。你给它一个股票代码，它输出一份
带证据链的财务分析报告。

它做四件事：

1. **取数** —— 从巨潮资讯网抓公告原文，从数据接口取结构化财务数据
2. **计算** —— 还原口径、算同比环比、算衍生指标（全部由代码完成）
3. **识别** —— 勾稽校验数据是否自洽，规则引擎识别异常信号
4. **归因** —— 大模型基于事实提出假设，并回到原文核实

一条关键设计：**数字全部由代码产生，大模型只做归因推理**。
所以报告里每个数都能回溯，每次运行结果都一致。

## 二、图形界面（双击启动）

不想敲命令就用这个。双击项目根目录下的：

```
启动FinAgent应用.bat
```

浏览器会自动打开 `http://127.0.0.1:8765/`。界面是对话式的，左侧栏切换四个页面：

| 页面 | 用途 |
|---|---|
| 对话 | 直接用自然语言提问，例如「分析牧原股份 2026 年中报为什么亏损」；系统先识别出公司，再判断该走分析、抓取还是建索引。回答下方给出关键指标速览卡与报告入口 |
| 报告 | 阅读生成的九章分析报告，可切换到对应的指标宽表逐格核对，并一键导出 PDF |
| 执行轨迹 | 逐条核对文件访问、工具调用、计算过程与结论依据；可按事件类型筛选，点任意一行展开原始 JSON |
| 环境 | 模型与密钥状态、语料规模、索引块数、全市场覆盖抽样，以及全部异常判定阈值 |

界面上有三个开关值得留意：

- **密钥**：右上角「API Key」填入自己的 DeepSeek 密钥即可开始分析。密钥只在本机使用，
  不写入任何文件，不回传到服务端日志；勾选「记住」才会存进浏览器 localStorage。
- **日志**：右下角悬浮按钮打开运行日志抽屉，实时显示服务端下发的原始事件。
  对话区只显示压缩过的执行摘要（调了哪些工具、读了哪些文件），要抠细节时看日志。
- **主题**：右上角切换浅色 / 深色；桌面端与窄屏都有对应布局。

对话里能识别的动作有三个，界面会从提问中自动判断：

- **执行财务分析** —— 智能体驱动，需要大模型密钥
- **抓取公告原文** —— 需要联网，用于构建封闭数据环境
- **建立公告全文索引** —— 完全离线

**界面与命令行完全等价**。界面不参与任何计算，它只是把参数翻译成
`run.py` 命令并转发输出；界面上会显示本次实际执行的命令，复制到终端运行结果一致。
运行轨迹照常落在 `output/traces/`，不受界面影响。

**导出 PDF**：报告页与对话中的报告卡片都带 PDF 按钮。服务端把 Markdown 渲染成
打印级 HTML，再调用本机已装的 Edge / Chrome 无头模式打印成 PDF，不引入额外依赖；
找不到浏览器时自动退化为浏览器打印对话框。可用 `FINAGENT_BROWSER` 环境变量指定浏览器路径。

- 界面只监听 `127.0.0.1`，且只允许读取项目内的 `output/`、`data/`、`docs/` 目录。

## 三、环境准备

### 需要什么

- Python 3.10 或更高（开发验证环境为 3.12.0）
- 约 100 MB 磁盘（公告原文约 60 MB）
- 网络（仅 `fetch` 命令需要；分析阶段完全离线）

### 安装

```powershell
cd D:\codex\比赛
pip install -r requirements.txt
python tests/check_env.py
```

`check_env.py` 会逐个核对依赖版本。看到「环境自检：通过」即可。

> 依赖版本已在 `requirements.txt` 中固定，目的是让评审环境与开发环境一致，
> 避免因库版本差异导致计算结果漂移。

## 四、三步跑通

### 第一步：构建数据环境

```powershell
python run.py fetch
```

从巨潮资讯网抓取配置中各公司的定期报告原文（年报、半年报、一季报、三季报），
落盘到 `data/corpus/<股票代码>/`。

**只需执行一次。** 重复执行会跳过已下载的文件，不会重复下载。

### 第二步：建立全文索引

```powershell
python run.py index
```

抽取 PDF 文本并建立 BM25 索引，产物在 `data/corpus_index/`。

24 份公告约需 3 分钟。**只需执行一次**（除非新增了公告，此时用 `--force` 重建）。

### 第三步：执行分析

```powershell
python run.py analyze
```

产出报告。默认分析 `config.yaml` 中配置的全部公司。

> **当前工作区已完成前三步**，你可以直接跳到第三步。

## 五、命令详解

| 命令 | 作用 | 是否需网络 |
|---|---|---|
| `python run.py search` | 在全市场名录中检索公司代码 | 不需要 |
| `python run.py fetch` | 抓取公告原文 | 需要 |
| `python run.py index` | 建立全文索引 | 不需要 |
| `python run.py analyze` | 执行财务分析 | 不需要 |
| `python run.py mcp` | 以 MCP 协议暴露工具集 | 不需要 |

### search —— 先查代码再分析

```powershell
python run.py search 茅台              # 按简称查
python run.py search 600519            # 按代码查
python run.py search 牧原 京东方 贝特瑞  # 一次查多个
```

名录内置 6259 只证券（沪深北 + B 股），离线可查，不消耗网络请求。

### 分析任意上市公司

`--code` 三种写法都接受，不需要事先在 `config.yaml` 里登记：

```powershell
python run.py analyze --code 002714        # 纯代码
python run.py analyze --code 002714.SZ     # 带后缀
python run.py analyze --code 牧原股份       # 公司简称
python run.py analyze --code 601398.SH     # 银行（自动切到银行报表族）
python run.py analyze --code 830964        # 北交所（自动处理 .BJ/.NQ 数据分裂）
```

银行、保险、证券使用专用报表格式，系统会先探明该主体属于哪一族再取数；
北交所有些公司的三张表分散在两个代码下，系统会**按报表逐个确认取数代码**。
这两件事都不需要你干预，但都会写进 `output/traces/` 供核对。

### fetch 参数

```powershell
python run.py fetch --code 002714        # 只抓某一家
python run.py fetch --limit 5            # 每类报告保留5份（默认3份）
```

### analyze 参数

```powershell
python run.py analyze                          # 分析配置中的全部公司
python run.py analyze --code 002714.SZ         # 只分析指定公司（可重复使用）
python run.py analyze --since-year 2025        # 只报告该年份及之后的结论
python run.py analyze --periods 8              # 报告展示8个报告期（默认6）
python run.py analyze --refresh                # 忽略缓存重新取数
python run.py analyze --quiet                  # 不打印工具调用过程
```

**推荐组合**：

```powershell
# 快速迭代（不看过程）
python run.py analyze --quiet

# 演示用（能实时看到模型在调什么工具）
python run.py analyze --code 002714.SZ
```

### 全局参数

```powershell
python run.py --config my_config.yaml analyze   # 使用指定配置文件
```

## 六、配置详解

配置文件为 `config.yaml`。优先级：内置默认值 < 配置文件 < 环境变量。

### data —— 数据路径

```yaml
data:
  cache_dir: data/raw          # 接口数据缓存
  corpus_dir: data/corpus      # 公告原文（封闭数据环境）
  index_dir: data/corpus_index # 全文索引
  refresh: false               # 是否每次强制重新取数
```

### companies —— 分析对象

```yaml
companies:
  - code: 002714.SZ
    name: 牧原股份
    industry: 生猪养殖
```

**配置外的公司也能分析**。直接 `--code 600519.SH`，系统会自动从数据源解析公司名。
但公告原文必须先通过 `fetch` 落盘，否则无法检索验证。

### llm —— 大模型

```yaml
llm:
  base_url: https://api.deepseek.com/v1
  api_key: ""          # 建议用环境变量注入，不要写进版本库
  model: deepseek-chat
  temperature: 0.2
  timeout: 120
```

### agent —— 智能体行为

```yaml
agent:
  max_steps: 12        # 工具调用循环的步数上限
```

调大能让模型查得更充分，但更慢更贵。12 是实测的平衡点。

### thresholds —— 异常判定阈值

```yaml
thresholds:
  impairment_yoy_pct: 300.0          # 减值同比增幅告警线
  impairment_min_amount: 100000000.0 # 减值告警的最小绝对额（1亿）
  nonrecurring_ratio_pct: 20.0       # 非经常性损益占比告警线
  adjusted_cash_conv_low: 0.5        # 调整后现金含量正常区间下界
  adjusted_cash_conv_high: 1.8       # 上界
  qoq_swing_pct: 50.0                # 单季环比波动告警线
  tax_rate_high_pct: 25.0            # 有效税率偏高判定线
  collect_ratio_low: 0.9             # 收现比告警线
  articulation_tol_pct: 0.5          # 勾稽校验容差
  depr_to_revenue_high_pct: 15.0     # 重资产判定线
```

阈值集中在配置文件而非散落在代码里，便于评审复现与按行业调参。

## 七、接入大模型

### 方式一：在图形界面里填（最简单，推荐）

双击 `启动FinAgent应用.bat`，打开界面右上角的「API Key」，填入自己的密钥即可。
密钥只在本机内存与浏览器里使用，不写入任何文件；勾选「记住」才会存进浏览器 localStorage。
同一台机器换人用，换掉密钥即可，不用改环境变量。

### 方式二：环境变量

PowerShell：

```powershell
$env:FINAGENT_API_KEY = "sk-xxx"
$env:FINAGENT_BASE_URL = "https://api.deepseek.com/v1"
$env:FINAGENT_MODEL = "deepseek-flash"
python run.py analyze
```

> 环境变量只在当前终端窗口有效。要长期生效用 `setx`，但注意 `setx` 会把密钥
> 明文写入注册表。

### 方式三：写入 config.yaml

把 `api_key` 填上即可。**不要提交到版本库**。

### 支持的国产模型

| 模型 | base_url | 示例 model |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-flash` / `deepseek-v4-pro` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-32k` |

### 不配密钥会怎样

系统自动降级为**确定性离线模式**：取数、计算、校验、规则识别、报告生成**全部照常工作**，
只有「归因分析」章节改为规则结论的整理。任务流程与输出结构完全一致。

这是有意设计的：评审在无密钥环境下也能复现完整流程。

## 八、产物怎么读

### 目录结构

```
output/
  reports/
    002714_牧原股份_财务分析报告.md      ← 主报告
    002714_牧原股份_结论.json            ← 结构化结论，供程序化复核
    跨公司对照分析.md                    ← 多公司同口径对照
  tables/
    002714_牧原股份_指标宽表.csv         ← 42科目 × 40报告期
  traces/
    20261007T190007-758abbd0.jsonl      ← 完整执行轨迹
```

与图形界面相关的文件在项目根目录：

```
启动FinAgent应用.bat    ← 双击启动图形界面
app/
  server.py             ← 界面服务端（纯标准库，只做转发与渲染）
  static/
    index.html          ← 页面结构
    style.css           ← 样式
    md.js               ← 极简 Markdown 渲染（不引入第三方库）
    app.js              ← 交互逻辑
```

### 报告章节

| 章节 | 内容 | 怎么用 |
|---|---|---|
| 执行摘要 | 总体判断 + 结论分类统计 | 先看这 |
| 一、关键财务指标 | 6期 × 11项指标 | 快速把握全貌 |
| 二、同比与环比 | 累计值 + 单季度值 + 三种比率 | 看单季度还原是否正确 |
| 三、异常信号 | 每条含事实/推论/验证路径/证据ID | 核心章节 |
| 四、归因分析 | 模型的归因假设与置信度 | 注意看置信度 |
| 五、勾稽校验 | 恒等式与间接法反推结果 | 判断数据是否可信 |
| 六、事实与推论 | 分层列表 | 检查有没有混写 |
| 七、证据索引 | 证据ID → 指标 → 口径 → 来源 | 回溯用 |
| 八、智能体执行轨迹 | 工具调用序列 + 提示词版本哈希 | 看它查了什么 |
| 九、局限性 | 已知边界与待验证项 | 别跳过 |

### 三类结论务必区分

- **异常信号** —— 数据偏离常态，需要解释
- **结构性特征** —— 看似异常，实为资产结构使然（如重资产企业现金含量虚高）
- **口径提示** —— 计算口径本身有限制

把第二类误报成第一类，是财务分析里最常见的低级错误。

### 证据 ID 怎么用

报告里每个数值都带形如 `EM-09B2C930D1` 的证据 ID。它由
「股票代码 + 报告期 + 报表 + 源字段」哈希生成，**同一组输入永远得到同一个 ID**。

拿着它可以从 `结论.json` 里找到对应条目，再对照 `指标宽表.csv` 核对数值，
最后回到 `data/corpus/` 的公告原文逐字确认。

### 轨迹怎么看

`output/traces/*.jsonl` 每行一个事件，`seq` 字段单调递增，可逐条重放：

```powershell
# 看这次运行动了哪些文件
Get-Content output/traces/<运行编号>.jsonl | Select-String '"event": "file_access"'

# 看模型调了哪些工具
Get-Content output/traces/<运行编号>.jsonl | Select-String '"event": "tool_call"'
```

事件类型：

| 事件 | 含义 |
|---|---|
| `run_start` / `run_end` | 运行起止 |
| `step` | 阶段耗时 |
| `file_access` | 读了/写了哪个文件 |
| `tool_call` | 调用了哪个工具、参数与结果 |
| `compute` | 算了哪个指标、公式是什么 |
| `agent_start` / `agent_end` | 智能体的模式、提示词与技能版本哈希 |
| `finding` / `result` | 识别到的信号与最终产物 |

## 十、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `fetch` 全部失败 | 网络不通或巨潮接口变更 | 检查网络；确认 `http://www.cninfo.com.cn` 可访问 |
| `fetch` 某公司返回 0 条 | 上市地与查询口径不匹配 | 已修：按代码前缀自动推断沪深北市场，查不到时再回退其它口径。若仍为 0，核对该代码在巨潮是否真有定期报告 |
| `index` 很慢 | 首次抽取全部 PDF | 正常，几十秒到几分钟。之后走缓存，只处理新增公告 |
| 双击 `启动FinAgent应用.bat` 窗口一闪而过 | 系统找不到 `python` | 重装 Python 并勾选 "Add python.exe to PATH"，或先在终端 `python --version` 确认 |
| 界面打不开，提示端口占用 | 8765 已被占用 | 换端口：`python app\server.py --port 8899` |
| 界面里点「执行分析」立即报错 | 大模型密钥未配置 | 设置 `FINAGENT_API_KEY` 后重启界面（`启动FinAgent应用.bat` 会自动读取 `DEEPSEEK_API_KEY`） |
| `search_disclosure` 返回空 | 索引未建立，或代码口径不匹配 | 先跑 `run.py index`；检索时用 6 位代码 |
| 报告里某指标全是 `—` | 季报不披露该数据 | 正常。如折旧摊销仅在中报/年报可得 |
| 报告里出现 `nan` | 分母非正 | 已修，应为 `—`。若仍出现请反馈 |
| 模型调用报错 | 密钥无效或额度不足 | 检查 `FINAGENT_API_KEY`；无密钥时会自动降级离线 |
| 分析很慢（每家2分钟） | 大模型模式 | 正常。快速迭代用离线模式或 `--quiet` |
| 结论与上次不同 | 大模型模式有随机性 | 事实层结论来自规则引擎，应完全一致；若不一致请查轨迹 |

### 大模型模式的成本参考

实测牧原单家公司完整分析（8 步工具循环）：

- 耗时约 116 秒
- 9 次模型调用
- 输入约 198k token，输出约 27k token

想省钱就用 `deepseek-flash`；需要更深推理再用 `deepseek-v4-pro`。
旧别名 `deepseek-chat` / `deepseek-reasoner` 同样可用。拿不准就留空，系统会用默认值；配错了会直接报 400。

## 十一、常见问题

**Q：为什么报告里有些格是横杠？**

季报不披露现金流量表补充资料，折旧摊销取不到。此时系统**留空而不是用近似值替代**——
如果强行按公式算，"调整后现金含量"会静默退化成"朴素现金含量"，
给出一个看起来正常的假值，那比留空危险得多。

**Q：为什么"经营现金流远高于净利润"没有报警？**

因为那通常是折旧摊销造成的结构性特征，不是异常。系统会先用
`经营现金流 / (净利润 + 折旧摊销 + 减值计提)` 做调整，
只有调整后仍显著偏离 1 才判定为异常。直接看朴素口径会把面板、钢铁、
电力等重资产行业全部误报。

**Q：怎么判断结果可信？**

三个地方：

1. 看「勾稽校验」章节——资产负债表恒等式是否全部通过，间接法残差多大
2. 看结论有没有证据 ID，点得回去
3. 看「智能体执行轨迹」——模型有没有真的去查原文，还是只复述了规则结论

**Q：能分析港股美股吗？**

目前只支持 A 股。数据源与公告检索都基于境内披露体系。

**Q：怎么确认改了提示词之后效果变好了？**

对比两次运行轨迹里的 `prompt_hashes`。提示词和技能的内容哈希都写入轨迹，
"这份输出由哪一版方法论产生"是可验证的。

## 十三、分发给队友

四种方式，按场景选：

| 方式 | 队友需要装什么 | 适合场景 |
|---|---|---|
| 公网展示站 | **什么都不用装** | 把结果发给队友、老师或评委，人不在同一网络也能看 |
| 局域网共享 | **什么都不用装** | 组会、答辩前一起看结果、临时演示 |
| 拷贝文件夹 + 一键安装 | Python 3.10 以上 | 队友各自独立跑、各自改代码 |
| Git 仓库 | Python 3.10 以上 | 长期协作改代码、要版本历史和分工 |

### 方式一：公网展示站（队友不在同一局域网时用这个）

把已经跑出来的真实产物固化成一个**只读静态站**，托管到免费的公网服务上，
队友打开网址就能看报告、指标宽表、执行轨迹和 PDF，不需要装任何东西，
也不需要和你在同一个网络。

构建：

```bash
python scripts/构建展示站.py --zip
```

产物在 `dist/FinAgent-展示站.zip`（约 4.6MB）。上传方式二选一：

- **Cloudflare Pages**：登录 <https://dash.cloudflare.com/> →
  Workers 与 Pages → 创建 → Pages → 上传资产 → 项目名填 `finagent` →
  把 zip 拖进去。几十秒后得到 `https://finagent.pages.dev`。
- **GitHub Pages**：把 `dist/cloudflare-pages/` 的内容推到仓库的 `gh-pages` 分支
  （或 `main` 的 `/docs` 目录），在仓库 Settings → Pages 里选好来源即可。
  展示站的资源引用是相对路径，放在域名子目录下也能正常打开。

站点的边界要讲清楚：它是**只读**的，只能浏览历史产物，不能在网页上发起新分析——
完整分析要读公告原文、跑规则引擎和调用大模型，这些留在本地做。站点里不含任何密钥。
想更新内容，重新构建后再传一次即可，网址不变。

### 方式二：局域网共享（最快）

1. 双击 `启动FinAgent应用（局域网共享）.bat`
2. 把窗口里「队友打开 …… ← 推荐发给队友」那一行的地址发给队友，
   形如 `http://10.11.103.8:8765/`
3. 队友浏览器打开即可，**不用装 Python，也不用拿到项目文件**

首次启动 Windows 会弹防火墙提示，勾选「专用网络」并允许访问，否则队友连不上。

两点注意：

- 分析实际跑在**你的机器**上，用的是你的密钥和你的算力。
- 同一时刻只允许一次运行。队友正在跑时，其他人的界面会显示「他人正在运行」并禁用按钮。
  这是有意设计——避免两条流水线同时覆盖 `output/` 下的产物。

窗口里若还列出「其它地址 ← 虚拟网卡，一般不用」，那是 VPN 或虚拟机网卡的地址，不要发给队友。

### 方式三：拷贝文件夹 + 一键安装

把项目文件夹打包发给队友，队友两步搞定：

1. 双击 `一键安装依赖.bat` —— 创建 `.venv` 隔离环境，按 `requirements.txt` 安装依赖，约 2 分钟
2. 双击 `启动FinAgent应用.bat`

`.venv/`（约 185MB）不用拷，各人本地自建更干净。

安装脚本默认走清华镜像。这**不是可选项**：实测国内直连 PyPI 会长时间停滞不动，
必须走镜像。镜像不可用时脚本会自动回退官方源，也可自行修改脚本里的 `MIRROR` 变量。

想省掉抓取步骤，就把 `data/corpus/`（约 74MB）一并拷过去，队友无需联网即可分析；
不拷则让队友自己跑一次 `python run.py fetch`。

### 方式四：Git 仓库

`.gitignore` 已经配好，默认**不**提交这些内容：

| 不提交 | 原因 | 队友怎么补 |
|---|---|---|
| `.venv/` | 185MB，且与具体机器相关 | 跑 `一键安装依赖.bat` |
| `data/corpus/` | 74MB 公告原文 | 跑 `run.py fetch`，或你单独分发 |
| `data/corpus_index/` | 16MB，可由 PDF 重建 | 跑 `run.py index` |
| `data/raw/` | 接口缓存 | 自动重新拉取 |
| `output/traces/` | 每次运行都新增，噪音大 | 自动生成 |

若希望队友克隆下来就能直接分析、不用联网抓取，把 `.gitignore` 里
`data/corpus/` 那一行注释掉再提交即可。

### 关于大模型密钥

密钥**不要**写进 `config.yaml` 提交，也不要在群里明文发。两种做法：

- **各人各自申请**（推荐）：队友在 DeepSeek 等平台自行注册，然后设环境变量
  `FINAGENT_API_KEY`
- **共用一把**：把密钥私发给队友，各自设成本机环境变量

不配密钥也能用：系统自动回落到确定性离线模式，计算、校验、报告照常产出，
只是没有模型提出的归因假设与验证路径。

### 展示站与本地应用的分工

两者不是替代关系，别混着用：

| | 展示站（静态） | 本地应用（`启动FinAgent应用.bat`） |
|---|---|---|
| 能做什么 | 浏览已产出的报告、宽表、轨迹、PDF | 发起新分析、抓公告、建索引、导出 PDF |
| 需要什么 | 一个浏览器 | Python 3.10 以上 + 大模型密钥 |
| 数据从哪来 | 构建时固化的真实产物 | 现场实时运行 |
| 适合 | 发链接给队友 / 评委 / 老师看 | 自己分析、答辩现场演示 |

### 关于打包成 exe

暂时不建议，原因是架构性的：本应用以**子进程**方式调用 `run.py`，
打成单文件 exe 后 `sys.executable` 指向 exe 自身，子进程无法再启动 `run.py`。
要支持 exe 需要把 CLI 改成进程内调用，属于结构性改造，不是加个打包参数就行。
