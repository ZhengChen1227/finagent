# FinAgent · 智金工坊

> 把财报 PDF 拖进界面，跑出一份能逐条回溯到原页码的财务分析报告。

**2026 年北京市大学生金融人工智能竞赛 · 选题 2「上市公司财务报告分析」参赛作品。**

FinAgent 是一个**本地运行**的财务分析智能体。用户上传上市公司的年报 / 半年报 / 季报 PDF，
系统从 PDF 原文中抽取财务数据、计算同比与环比、识别非经常性损益与会计口径变化、
检验利润与现金流的背离，最终输出结构化数据、指标宽表与可下载的 PDF 分析报告。

> **算数交给代码，归因交给大模型。**
> 每一个数字都来自确定性计算层并携带证据编号，模型只负责检索证据、解释成因与组织表达。

## 一、三条产品铁律

| 铁律 | 含义 | 为什么 |
|---|---|---|
| **只有一种使用方式** | GitHub 下载 → 双击 `一键安装依赖.bat`（仅首次）→ 双击 `启动FinAgent应用.bat` → 浏览器自动打开 | 答辩现场不能有"先配环境"这一步 |
| **没有离线模式** | 未填 DeepSeek API Key 时点「开始分析」直接拦截并弹出密钥窗，不产出任何替代结论 | "能绕过模型"的降级分支会让智能体退化成固定流水线 |
| **只吃上传的财报** | 界面没有公司名 / 股票代码输入框；公司身份从 PDF 正文解析 | 财务数据全部来自用户上传的封闭材料，运行期不联网取数 |

## 二、快速开始

### 1. 装一次依赖

```
双击  一键安装依赖.bat
```

脚本会检查 Python 版本（需 3.10+）、创建项目私有的 `.venv`、按 `requirements.txt`
安装固定版本依赖并做一次环境自检。装完只需做这一次。

### 2. 启动

```
双击  启动FinAgent应用.bat
```

服务只监听本机 `127.0.0.1:8765`，浏览器会自动打开操作界面。
**关闭那个黑窗口就等于停止服务。**

### 3. 用

1. 点右上角「填写 API Key」，粘上你自己的 DeepSeek API Key，点「测试连接」→「保存」；
2. 把财报 PDF 拖进上传区（可一次拖多份）；
3. 看一眼识别结果：每份文件会显示解析出的**主体名称 + 报告期**；
4. （选填）在「定向追问」里写下你特别想弄清的问题，例如"为什么利润涨了现金流却跌了"；
5. 点「开始分析」，等结果。

> **不需要同一个局域网。** 每台电脑跑自己的一份：自己的 Key、自己的财报、自己的产物。
> 队友只需拿到同一份代码，不必和你在同一网络下，也不需要你开机。

## 三、界面

| 页面 | 看什么 |
|---|---|
| **分析工作台** | 上传区、待分析清单、定向追问、运行状态、运行日志抽屉 |
| **分析报告** | 渲染后的 Markdown 报告 + 「下载 PDF」按钮 |

运行日志单独收在抽屉里，不干扰主界面。

## 四、输出物

每次运行固定产出四类东西，缺一不可：

```
output/
├── reports/<主体>_财务分析报告.md     人类可读的分析报告
├── reports/<主体>_结论.json           结构化结论（便于程序化复核）
├── tables/<主体>_指标宽表.csv         指标宽表（含同比 / 环比 / 证据页码）
└── traces/<run_id>.jsonl              完整执行轨迹，可逐条重放
```

报告页可以一键导出 PDF（走系统已装的 Edge / Chrome 打印，不引入额外依赖）。
多主体一起上传时，另外产出 `output/reports/跨主体对照分析.md`。

## 五、它是怎么工作的

```
上传 PDF
   │
   ├─ ingest/     版面还原抽取 ──► 合并资产负债表 / 合并利润表 / 合并现金流量表
   │                              主要会计数据 / 非经常性损益 / 分季度指标
   │
   ├─ verify/     交叉校验闸门 ──► 自算同比 vs 报告披露同比、资产=负债+权益、
   │                              小计=明细之和、单季还原 vs 分季度表
   │
   ├─ metrics/    指标计算     ──► 同比 / 环比 / 现金含量 / 扣非后利润 / 周转与结构指标
   │
   ├─ validate/   规则引擎     ──► 异常信号、结构性特征、口径提示三类结论
   │
   ├─ agent/      大模型编排   ──► ReAct 循环调用工具取证，产出归因推理
   │
   └─ report/     报告生成     ──► Markdown / JSON / CSV / PDF + 全链路轨迹
```

关键设计是**抽取层产出统一的 canonical 契约**（`finagent/datasource/schema.py`）：
无论财报长什么样，下游拿到的都是同一组字段名。数据源换过一次，下游四层没有改写。

### 目录职责

```
finagent/
  ingest/          PDF 版面抽取、主体识别、报表装配、交叉校验闸门（本轮新增）
  datasource/      canonical 字段契约与科目同义词表
  corpus/          上传材料的全文索引与检索
  metrics/         指标计算（纯函数，可单独测试）
  validate/        勾稽校验与异常规则引擎
  agent/           编排循环、工具集、Prompt、Skill
  report/          报告与结构化结论生成
  mcp_server.py    MCP 协议服务端
app/               本地 Web 界面（标准库 http.server + 原生前端，无第三方框架）
run.py             命令行入口：analyze / index / mcp
tests/             11 套测试，`python tests\run_all.py`
```

## 六、为什么它的数字可信

**交叉校验闸门（`finagent/ingest/verify.py`）**是这套系统最硬的一块。
抽完数字不算完，还要过四道闸门：

1. **自算同比 vs 报告披露的同比** —— 差异超过 ±0.05 个百分点就报警；
2. **资产 = 负债 + 所有者权益** —— 恒等式不成立说明抽错了行；
3. **小计 = 明细之和** —— 例如经营 / 投资 / 筹资现金流合计对不上净增加额；
4. **单季还原 vs 年报分季度表** —— 累计值倒推的单季数必须和报告自己披露的对得上。

**任何一项不通过，该科目就被降级为「需人工复核」并在报告里标出来，绝不静默输出可疑数字。**
一份写着"该项未能从财报中抽取"的报告，远好于一份写着错数字的报告。

另外两条：

- **三态取数**：`抽到 / 财报确实没披露 / 抽取失败`，三者严格区分，绝不把失败折叠成"没有数据"。
- **事实与推论分离**：结论对象在数据结构上就把 `statement`（事实）和 `interpretation`（推论）分开，
  模型不能把猜测写成事实。

## 七、命令行（评审复现用）

界面是给演示用的；要复现流程，命令行更直接：

```bash
python run.py analyze --pdf 财报1.pdf 财报2.pdf     # 分析指定的 PDF
python run.py analyze --pdf-dir data/corpus/002714  # 分析目录内全部 PDF
python run.py index --force                          # 为本次上传材料重建全文索引
python run.py mcp                                    # 以 MCP 协议暴露工具集
```

`analyze` 支持 `--run <上传批次>` 复用已解析结果、`--question "..."` 带上定向追问、
`--quiet` 关闭工具调用日志。全部参数见 `python run.py analyze --help`。

## 八、复现清单

仓库**不打包财报 PDF**（单份最大 6.7MB，36 份共 74MB，且属于第三方披露文件）。
需要复现的评审方请按 **`docs/复现清单.md`** 从巨潮资讯网自行下载：
清单里给了每份公告的标题、下载链接、公告编号与 SHA256，下载后校验哈希即可确认拿到的是同一份文件。

本机没有语料时，集成测试会明确跳过并提示；单元测试（`tests/test_ingest.py`）
使用合成版面文本，**任何机器上都能跑**，不依赖任何 PDF。

## 九、已知限制

如实披露，不掩盖：

- **银行 / 保险 / 证券**的报表格式与工商业差异很大。开发机上没有这三类样本，
  目前靠同义词变体与规则兜底，**未经真实样本验证**。首次拿到这类财报时必须优先回归。
- **只上传单份半年报或季报**时，年内缺少上一期累计数，**环比不可计算**。
  报告会如实标注"不可计算"，不臆造数字。年报自带「分季度主要财务指标」，环比可直接还原。
- 万字单位换算（万元 / 千元）已由合成测试覆盖，但**没有真实万元报表样本**。
- 少数同义词槽位（生物资产折旧、递延收益摊销等）目前为空，遇到相应报表会留空并标注。
- **部分科目本公司根本不单独列示**，这不是抽取缺陷。例如牧原与京东方近年现金流量表
  把「收到的税费返还」并入「收到其他与经营活动有关的现金」，系统会留空并写进 missing 清单，
  不会拿相近科目顶替。
- 因此**抽取科目数会因公司、因报表而异**。实测参考：京东方 2025 年报利润表 18/20、
  现金流量表 12/20，而同期半年报为 20/20 与 20/20——差异来自报表本身的结构，不是程序漏抽。
- 财报 PDF 的来源、版本与完整性由使用者负责。系统只对"抽出来的数字是否自洽"负责。

## 十、网络边界

| 允许出网 | 用途 | 时机 |
|---|---|---|
| `https://api.deepseek.com` | 大模型推理（用户自己的 Key） | 每次分析 |
| PyPI | 安装依赖 | 仅首次 |
| GitHub | 获取代码 | 仅用户下载时 |

除此之外**运行期不发任何网络请求**。服务硬编码监听 `127.0.0.1`，
命令行也不提供 `--host` 参数——这是"半封闭数据环境"的工程证据，不是配置疏漏。
`tests/test_network.py` 用审计钩子实测运行期出网请求，只允许 DeepSeek 一个域名。

## 十一、常见问题

| 现象 | 原因与处理 |
|---|---|
| 双击 bat 一闪而过 | 先用 `.bat` 里提示的方式在命令行跑一次，看报错；多数是 Python 未装或未加进 PATH |
| 提示"请先填写你自己的 DeepSeek API Key" | 这是**设计如此**的硬拦截。点右上角「设置」填入 Key |
| 「测试连接」失败 | Key 无效 / 额度不足 / 网络不通，三者之一，逐项排查 |
| 某份 PDF 识别不出主体 | 界面会标红并要求确认。换个更完整的版本（有些摘编版没有封面页） |
| 报告里出现「需人工复核」 | 说明该科目没通过交叉校验。这是特性，不是 bug——请点开轨迹看是哪一项不过 |
| 下载 PDF 没反应 | 需要本机装有 Edge 或 Chrome。没有的话用系统的打印功能另存为 PDF |
| 分析很慢 | 大模型逐条取证本来就慢。快速看结果可以先用 `--quiet` 跑命令行 |
